# AI 产品经理转型学习系统｜章节制作框架 v1

每章都使用同一条学习闭环：`状态核对 → 概念主线 → 机制拆解 → 边界判断 → 可控实验 → 正式单题 → 迁移练习 → 产出与复盘`。

## 1. 章节契约

- 本章要解决的一个核心问题；
- 前置掌握状态与不复测范围；
- 本章正式概念、延期概念和下一章门槛；
- 可检查产出，而不是“看完课程”。

## 2. 概念主线

- 英文全称、中文全称和一句通俗解释；
- 该概念在 AI 产品链路中的位置；
- 模型、确定性程序、人工各自负责什么；
- 最常见的一个错误心智模型。

## 3. 机制拆解组件

每个机制至少回答四项：

1. 当前环节在回答什么问题；
2. 输入或触发条件来自哪里；
3. 系统、模型或人工分别执行什么；
4. 用什么日志、证据或测试确认它工作正确。

页面使用 `assets/concept-mechanism.css` 与 `assets/concept-mechanism.js`。每个步骤通过 `data-mechanism-title`、`data-mechanism-question`、`data-mechanism-role`、`data-mechanism-check` 描述，不在脚本中硬编码课程内容。

## 4. 边界与反例

- 什么情况下适用；
- 什么情况下不适用或必须降级；
- 与相邻概念的区别；
- 至少一个“看起来合理但会失败”的反例。

## 5. 可控实验

- 一次只改变一个关键变量；
- 先给默认场景，再让学习者预测；
- 同时显示输入、规则判断、动作、结果和日志；
- 实验结果只用于理解，不修改正式掌握状态。

## 6. 正式单题接力

- 页面展示当前正式题与结构化答题骨架；
- 复制内容必须带 session_id 与 question_id；
- Codex 一次只评分一道题，保留学习者原话；
- 只有正式评分后才能回写状态、错题和复测关系。

## 7. 迁移练习

- 至少一个不同业务场景；
- 要求学习者说明哪些机制保持不变、哪些参数变化；
- 连接到 AI 产品经理的需求、方案、评测、风险或协作职责；
- 不用同义改写冒充迁移。

## 8. 产出与复盘

- 产出字段有结构、有版本、有验收条件；
- 三到五条本章总结；
- 明确当前正式状态和下一步；
- 页面自检、导出和浏览器完成度不得写成正式掌握。
