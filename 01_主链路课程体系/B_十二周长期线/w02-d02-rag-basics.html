把 RAG 放回产品系统：它是给模型补充可引用外部资料的检索层。

RAG 的价值不是“让回答更聪明”，而是让 AI 面试与项目答辩教练 Agent 在需要事实、证据和来源时有地方可查。今天先判断哪些场景需要检索，哪些场景只要 Prompt、规则或人工就够了。

RAG 什么时候值得上？

RAG 适合让模型基于外部资料回答，尤其是当问题依赖 JD、简历、项目材料或评分依据时。

0 / 2 步

事实来源

答案要引用什么

JD、简历、项目经历、评分 Rubric、历史反馈和作品集。

不等于：让模型自己记住所有事实

来源可查

答案能回到哪份材料

每个结论都要能指向原始来源或切片。

不等于：只给一段看起来很顺的话

新鲜度

哪些信息会变

项目进展、岗位要求、材料版本和答辩状态。

不等于：静态模型记忆可以一直正确
白话解释

RAG 像给模型加一个可引用的资料柜：先找材料，再让模型组织答案。

它不等于什么

它不是自动补全事实的机器，也不是把所有知识问题都一把梭。

错误写法只要把所有文档都丢进向量库，问题就会自动解决

没有判断问题是否依赖外部来源，也没有区分哪些问题其实该由 Prompt 或规则处理。

产品化写法当答案必须引用项目材料或岗位依据时，再把检索层接上

先判断是否需要 grounding，再决定检索什么、怎么引用和何时转交。

完整示范：面试教练为什么要上 RAG先判断是否需要引用证据

场景：用户问“我这个项目在这个岗位里算不算匹配？”

  1. 已知事实答案依赖岗位 JD、用户简历和项目材料。
  2. RAG 可做从 JD 与材料中找出可引用证据和缺口。
  3. RAG 不可做不能替用户补经历，也不能替岗位打最终录用结论。
  4. 产品动作输出“证据引用 + 缺口诊断 + 追问建议”，而不是直接给匹配分。

RAG 不能补什么：先做失败归因，再决定是否继续检索

RAG 不是把错误都藏进检索层。资料缺失、权限不足、切片过粗、引用字段缺失和时效过期，根因不同。

0 / 2 步

资料缺失

没有材料可查

JD、简历、项目经历或评分标准根本没提供。

权限不足

能看见的材料太少

有些文档不允许检索或展示给当前用户。

引用不完整

找到了却说不出来

没有引用字段、来源编号或可读片段。

白话解释

RAG 的失败不是“没开检索”，而是它只对有来源、有权限、有结构的资料有效。

它不等于什么

它不等于无限扩容的知识库，也不等于把所有问题都变成检索问题。

错误归因回答不稳，就多切几层文档

如果根因是没有资料或没有权限，切得再碎也不会变好。

正确归因先判断是材料、权限、切片、引用还是评测问题

不同失败信号对应不同处理层，不能只补检索。

完整示范：为什么模型引用不到项目材料先判根因，再补机制
  1. 现象Agent 总说“缺少项目证据”，但拿不出具体引用。
  2. 可能原因材料没录入、权限被拒、切片规则不对或引用字段没设计。
  3. RAG 可修增加可检索来源、引用格式和材料索引。
  4. RAG 不可修如果用户根本没提供项目材料，就应该追问，不该硬检索。

资料与切片边界：先整理来源，再谈检索

RAG 需要先知道有哪些材料、谁能用、多久更新一次，以及哪些字段要切给模型。

0 / 2 步

来源清单

有哪些文档

JD、简历、项目经历、Rubric、历史反馈、作品集和答辩记录。

权限边界

谁能看什么

哪些材料允许被检索、展示和引用。

切片规则

怎么拆最有用

按项目、按答案段落、按评分维度或按更新时间拆分。

白话解释

资料边界就是把可检索的内容变成清楚的清单，而不是把整个文件夹一股脑丢给模型。

它不等于什么

它不等于盲目堆文档，也不等于所有资料都默认可见。

危险写法把所有文档都喂给模型，反正越多越好

没有来源清单、权限和更新频率，RAG 会把脏资料一起放大。

更稳的写法先列来源、权限、切片和更新频率，再接检索

只有来源结构清楚，RAG 才能成为可维护的产品能力。

完整示范：把项目材料做成可检索资产先有来源，再有检索
  1. 来源从 JD、简历、项目原文和评分标准开始。
  2. 切片把项目经历、结果和证据分段，便于引用。
  3. 权限决定哪些内容可被当前用户检索到。
  4. 更新记录版本号和更新时间，避免检索到旧材料。

Prompt / RAG / 数据 / 人工分界：把职责拆开，Agent 才好治理

W2 选型的关键不是“要不要上 RAG”，而是把表达、引用、状态和高风险结论分到不同机制。

0 / 2 步

Prompt

负责表达和任务约束

控制格式、语气、步骤和追问策略。

RAG

负责来源引用

把外部资料送进模型判断。

数据

负责状态和字段

保存结构化信息、版本和结果。

人工

负责高风险确认

正式评分、发布和不可逆动作需要人确认。

白话解释

RAG 只是系统中的一层，它不能把检索、状态和正式结论全部包掉。

它不等于什么

它不等于完整产品，也不等于替代数据结构和人工审核。

危险分工检索、评分、保存状态和正式结论全让 RAG 兜住

这样一旦失败，很难知道该修哪一层。

可治理分工Prompt 负责表达，RAG 负责引用，数据负责状态，人工负责确认

职责清楚后，后续评测、日志和风险控制才站得住。

完整示范：答辩材料从哪一层来先分层，再实现
  1. Prompt要求模型输出缺口诊断和追问建议。
  2. RAG从项目材料里找可引用证据。
  3. 数据记录答辩状态、版本和历史反馈。
  4. 人工确认是否把建议写入正式作品集或简历。
