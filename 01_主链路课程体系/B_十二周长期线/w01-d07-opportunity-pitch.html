  1. 用户任务用户最先需要的是练习追问、修正回答，还是看复盘结果？

  3. 控制要求如果要写入正式评分或结论，就不能只靠聊天，需要更强的流程控制。
  4. 首版选择AI 面试与项目答辩教练 Agent 更适合“侧边教练 + 报告面板”的混合口述，而不是纯聊天。

不是把同一个能力到处复制，而是根据场景把它放到最顺手的位置。

完整示范：面试前练习和面试后复盘应当用同一个入口吗？入口不必一样，触点要对齐任务
  1. 练习阶段需要即时追问和引导，适合侧边教练或工作流入口。
  2. 复盘阶段需要结构化总结和证据回看，适合报告面板或结果页。
  3. 控制方式练习阶段可以多轮互动，复盘阶段更需要固定字段和可比对结果。
  4. 产品结论同一个 Agent 可以有多个触点，但每个触点必须服务一个明确任务。

关键判断不是背结论。AI 产品经理要把 W1 的判断压成能经得起追问的证据链：为什么做、凭什么做、哪里不做、失败怎么办。

白话解释

关键判断帮助你快速判断：这个任务更像随问随答、嵌入协作、步骤推进，还是结果汇总。

它不等于什么

不是把名词背熟就算会选型，而是要能说出每种证据的适用场景和缺点。

Chat

适合高频问答

围绕自然语言互动展开，适合用户随时补充信息。

缺点：容易失去流程边界

Copilot

适合嵌入式协作

贴着原任务页面给提示，不打断主工作流。

缺点：控制空间有限

Coach

适合训练和引导

通过步骤、反馈和复述帮助用户逐步进步。

缺点：设计成本较高

Workflow

适合流程型任务

按明确步骤推进，适合有状态、可回放的训练。

缺点：灵活性更低

Report

适合结果回看

把追问、证据、评分和建议整理成结构化报告。

缺点：不适合即时互动

问题：同一个产品要先服务练习还是先服务复盘？

  1. 练习场景更适合 Coach 或 Copilot，帮助用户逐轮练习追问和回答。
  2. 答辩前准备适合 Workflow，把训练步骤和证据收集串起来。
  3. 复盘场景适合 Report，把结果、证据和建议固定下来。
  4. 首版结论面试教练 Agent 的首版更像 Coach + Report 的混合口述。

风险与回退：口述决定谁点头、谁回退、谁看见结果

Agent 不是越自动越好。口述一旦涉及评分、结论、发布或不可逆动作，就必须明确哪里保留给人、哪里交给规则、哪里只给建议。

白话解释

风险与回退就是你允许用户和系统在哪一步按下“继续”“确认”或“回退”。

它不等于什么

不是把自动化做满，而是把高风险动作放在最安全的位置。

危险口述模型直接生成评分并写入通过状态

用户看见的是结论，看不见中间校验和证据，因此很容易误判。

可控口述模型先给建议，规则再校验，人最后确认

保留可回退和可解释的空间，适合面试和答辩这类高风险场景。

完整示范：答辩结论要不要自动给出风险越高，风险与回退越明确
  1. 建议层模型可以先给出“回答还缺结果证据”的建议。
  2. 规则层系统检查是否满足评分字段和证据引用要求。
  3. 人类层用户或教练确认是否继续、修改还是结束。
  4. 产品结论AI 面试与项目答辩教练 Agent 必须保留人工确认点，不能直接自动发布正式结论。
