先在脑中搭起一张图：评分不是“模型觉得像几分”。

证据驱动评分可以先理解为“先找原话，再按标准裁决”。模型可以帮忙抽候选证据和生成解释，但分数、缺口和正式结论必须能回到 Rubric 与原始回答。

先讲评分动作，再讲术语

每个英文词都先回答“谁规定标准，谁找证据，谁能给分”。

用错误评分划边界

不把流畅总结当证据，而是找出第一个无法回放的结论。

带着样例写报告

Rubric 是评分表，还是一句“答得完整给高分”？

Rubric 可以先理解为“评分尺子”。它要写清每一档看什么证据、缺什么不能给分，而不是让模型凭印象判断完整度。

0 / 2 步

Criterion

就是评分维度

例如事实定位、机制分工、风险边界。

能决定：看哪类证据不能决定：证据是否存在

Level

就是分数档位

每档要写出可观察行为，而不是“好、一般、差”。

能帮助：稳定裁决不能替代：原话引用

Gate

就是不能越过的门槛

例如没有原话证据时不得给非空分。

能阻止：模型自信补全不能伪造：正式掌握
白话解释

Rubric 像验收清单：不是“感觉完成”，而是每个等级都能指向具体证据。

它不等于什么

“回答全面给 3 分”不是好 Rubric，因为不同人和模型会把全面理解成不同东西。

看起来简洁，但错误3 分 = 回答很好

没有说明好在哪里，评分无法复核。

正确的产品链路维度 → 可观察行为 → 原话证据 → 分数门槛

先写清评分尺子，再让模型抽候选。

  2. 第一个错误节点评分尺子依赖主观印象。

  4. 保持不变每个分数档都要能被原话证据证明。

证据抽取是不是把回答总结一下就行？

证据是能回到原回答的具体片段。总结可能有用，但只有逐字原话、题号和回答身份能支撑正式评分。

证据像法庭里的原始材料。模型可以帮忙圈重点，但不能把改写后的摘要当原件。

完整示范：摘要多说了一个边界先回到原话

  1. 已知事实原话只支持制度，不支持三类事实源。
  2. 第一个错误节点摘要把模型推断当成证据。
  3. 正确动作缩小 claim，或标记证据不足。
  4. 保持不变评分证据必须来自原话或原始交付物。

有了证据，分数是不是模型说几分就几分？

分数裁决要把证据逐条对齐 Rubric。模型可以给候选分，但程序和评审规则要检查证据是否达到档位门槛。

0 / 2 步
白话解释

评分像验收。不是看到一个亮点就给满分，而是每个门槛都过了才进入对应等级。

它不等于什么

模型给出 0.82 置信度不等于 3 分；置信度不能替代 Rubric 对齐。

看起来高效，但错误候选 score=3 → 直接写入

没有逐项验证档位条件。

正确的产品链路候选分 → 证据对齐 → 门槛检查 → 分数或 null

分数必须小于等于证据能证明的等级。

完整示范：只满足 2 分却给 3 分先看缺失门槛

现象：学习者能定位事实和限制结论，但没有比较替代方案。

  1. 已知事实Rubric 的 3 分要求比较至少两个机制。
  2. 第一个错误节点把整体不错当成满档。
  3. 正确动作给 2 分，并把“缺少候选比较”写成最高优先缺口。
  4. 保持不变分数不能超过证据满足的最高档位。
理解检查：缺 3 分门槛时怎么判

回答满足 2 分条件，但缺少 3 分要求的候选比较。第一步应该怎么判？

留下一个理解或疑问

信息不足时，是不是应该猜一个低分？

信息不足不是低能力。它表示当前证据不够裁决。产品要保留 null、缺口原因和下一步，而不是硬给 0 分。

0 / 2 步
白话解释

没有拍到证据，不等于事情不存在。评分系统只能说“当前证据不足”，不能说“用户不会”。

它不等于什么

空回答可以是 0 分，但题目没覆盖、引用缺失、系统丢日志时应该是信息不足，不是低分。

看起来果断，但错误没看到证据 → 0 分

可能是题目没问到或证据丢失，不是能力失败。

正确的产品链路判断缺证原因 → score=null → 写 limitation → 安排补证

把“不知道”和“没做到”分开。

完整示范：题目没有问迁移不要给迁移 0 分

现象：面试只问了定义，没有给新场景题，报告给迁移 0 分。

  1. 已知事实迁移能力没有被采证。
  2. 第一个错误节点把未观察到当成失败。
  3. 正确动作迁移维度 score=null，写明未覆盖并安排复测。
  4. 保持不变无证据不等于负证据。
理解检查：没问到迁移怎么给分

当前 session 没有新场景迁移题，因此没有迁移证据。第一步应该怎么处理？

带着资料做一次：区分 0 分和 null

请写出三个场景：应该给 0 分、应该给 null、应该保留原分但补 limitation。

需要提示时展开

从空回答、题目未覆盖、引用不完整三个角度想。

方案已记录。

空回答或明确错误可给 0 分；题目未覆盖、证据丢失或 quote 不存在应给 null；回答部分可证但有范围限制时保留分数并写 limitation，例如“仅支持事实定位，不支持方案比较”。

留下一个理解或疑问

置信度高，是不是就能大胆发布结论？

置信表达是对当前证据和裁决稳定性的说明，不是模型语气有多自信。置信度必须受到证据完整性、Rubric 清晰度和校验结果限制。

0 / 2 步
白话解释

置信度像报告里的“我有多确定以及为什么”。它要解释证据够不够，不是写一个漂亮小数。

它不等于什么

模型输出 0.94 不等于可以发布正式结论；如果 quote 缺失，置信表达必须降级。

看起来量化，但错误confidence=0.94 → 正式通过

数字没有说明证据和标准是否满足。

正确的产品链路证据完整性 → 标准清晰度 → 校验结果 → 置信文字

用可解释原因表达稳定性。

完整示范：高置信但缺 quote先降级表达

现象：模型说 95% 确认用户掌握证据链，但没有逐字引用。

  1. 已知事实候选结论自信，但核心证据缺失。
  2. 第一个错误节点把模型自信当成证据完整。
  3. 正确动作置信表达降级为“无法确认”，并要求补 quote。
  4. 保持不变置信不能突破证据边界。
理解检查：高置信但无 quote 怎么写

模型给出高置信掌握结论，但没有逐字 quote。第一步应该怎么处理？

带着资料做一次：写置信表达

请为“有部分 quote、Rubric 清楚、但缺迁移题”的情况写一段置信表达和限制说明。

需要提示时展开

不要只写百分比，要说明哪些结论稳定，哪些不能确认。

方案已记录。

对机制解释有较高把握，因为 quote 能支撑事实定位和边界意识；不能确认新场景迁移，因为没有迁移题和对应 quote。结论应写为“部分通过，迁移待补证”，下一步安排新场景复测。

留下一个理解或疑问

评分报告为什么不能只写总分和建议？

评分报告要让读者从结论回到原题、原答、quote、Rubric 档位和下一步。总分只是结果，不是证据链。

0 / 2 步
白话解释

报告像可复核的判卷记录：不仅写几分，还写为什么、证据在哪里、哪里没观察到、下一步补什么。

它不等于什么

“综合表现良好，建议继续练习”不是评分报告，因为它无法回放也无法指导复测。

看起来友好，但错误总分 + 鼓励建议

没有证据、缺口和下一步，用户不知道如何改。

正确的产品链路结论 → 原话证据 → Rubric 档位 → 缺口 → 下一题/复测

报告必须能追溯和行动。

完整示范：报告无法复盘先补证据链

现象：报告写“2 分，证据意识一般”，没有引用回答。

  1. 已知事实有分数，但没有 question_id、answer_id 和 quote。
  2. 第一个错误节点报告无法被用户或评审复核。
  3. 正确动作补原题、原答片段、Rubric 档位、缺口和下一步。
  4. 保持不变正式报告必须从结论回放到证据。
