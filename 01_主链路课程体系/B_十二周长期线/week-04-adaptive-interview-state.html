追问是为了澄清一个高价值缺口，不是把面试变成无限聊天。次数、目标、题目身份和停止条件都要写清楚。

白话解释

追问像补拍一张关键证据照片。拍到证据就收，不该一直换角度拍。

它不等于什么

模型觉得还没聊透，不等于还能追问。追问必须和当前题、当前缺口、额度绑定。

看起来认真，但错误回答模糊 → 一直追问到清楚

无限追问会改变评测成本、时长和公平性。

正确的产品链路识别单一缺口 → 一次追问 → 记录是否补足 → 超额则进入下一题或结束

追问是受控补证，不是自由对话。

  1. 已知事实追问有价值，但 follow_ups_used 已等于上限。
  2. 第一个错误节点让内容价值绕过追问额度。
  3. 正确动作阻断追问，记录缺口，进入下一基础题或正式反馈。
  4. 保持不变追问必须服从额度、当前题身份和停止规则。

上下文是不是越多越安全？

自适应面试要带入必要历史，但不能把所有回答、评分和内部规则都塞给模型。上下文要服务当前判断，并保护正式状态边界。

0 / 2 步
白话解释

上下文像给面试官的简历摘要，只给当前问题必要信息。给太多会干扰判断，也可能泄露不该给模型的状态。

它不等于什么

完整历史不等于更公平。模型不需要看到正式 JSON 的全部字段，更不能根据历史字段直接改状态。

看起来完整，但错误所有历史回答 + 全部评分规则 → 模型决定下一步

会引入噪音，也让模型接触它不该决定的状态。

正确的产品链路当前题目标 → 必要证据摘要 → 禁止字段 → 模型候选 → 程序裁决

上下文最小够用，状态由程序读取和推进。

完整示范：历史噪音干扰追问先裁剪上下文

现象：模型看到三周前的错题，忽略当前题已经通过，继续追问旧缺口。

  1. 已知事实旧缺口已复测通过，当前题目标不同。
  2. 第一个错误节点把未过滤历史当成当前事实。
  3. 正确动作只传当前题、最近有效证据和仍未通过缺口。
  4. 保持不变上下文要按当前决策裁剪，而不是全量倒入。
理解检查：模型被旧缺口干扰怎么办

允许给模型：当前题目标、能力标签、必要回答摘要、仍未覆盖缺口。禁止给模型：完整正式 JSON、可写状态字段、内部评分阈值、敏感个人信息。程序读取正式状态并裁决下一步，模型只生成候选题目或追问。

状态机为什么不能让模型自己推进？

状态机就是流程事实表：当前在第几题、有没有待答题、追问次数、是否已完成。模型可以建议动作，但不能直接写状态。

0 / 2 步
白话解释

状态机像排队叫号系统。模型可以建议“下一位”，但叫号屏幕只能由系统规则更新。

它不等于什么

模型输出 next_state=completed 不是完成事实。完成必须来自服务端检查和证据覆盖。

看起来自动化，但错误模型说 completed → 页面结束

模型绕过了题目队列、证据覆盖和待答题检查。

正确的产品链路模型候选 action → Guard 检查 → 服务端状态迁移 → 页面投影

页面只展示状态，不能反向制造正式事实。

完整示范：旧题提交回来先核对 question_id

现象：用户提交的是上一题答案，但页面已经进入下一题。

  1. 已知事实提交 question_id 和当前 session 不一致。
  2. 第一个错误节点接受旧题提交并覆盖当前状态。
  3. 正确动作Guard 阻断 stale submit，提示刷新或恢复当前题。
  4. 保持不变所有状态迁移都要核对身份、顺序和权限。

留下一个理解或疑问

什么时候该结束、暂停或安排复测？

停止规则不是“答得差不多就结束”。它要说明覆盖完成、时间耗尽、证据不足、风险过高和延期复测各自怎么处理。

0 / 2 步
白话解释

停止规则像考试交卷规则：达到覆盖就结束，缺关键证据就标缺口，不能为了完成感硬判掌握。

它不等于什么

提前结束不等于通过；页面做完也不等于正式掌握。停止只是流程动作，掌握要看正式证据。

看起来友好，但错误用户答累了 → 标记掌握

疲劳只能触发暂停或降级反馈，不能生成掌握证据。

正确的产品链路覆盖检查 → 缺口记录 → 完成/暂停/复测 → 正式证据回写

停止原因必须可追溯。

完整示范：时间耗尽但迁移未覆盖先保留缺口

现象：面试时间到了，机制解释通过，但新场景迁移没有问到。

  1. 已知事实部分能力已覆盖，迁移证据缺失。
  2. 第一个错误节点因为流程结束就标记全部掌握。
  3. 正确动作标记课程完成但掌握缺口保留，安排新场景延期复测。
  4. 保持不变停止流程不能抹掉未覆盖证据层。
理解检查：时间到了但迁移没覆盖怎么办

机制解释已通过，迁移能力没有证据，面试时间已到。第一步应该怎么处理？
