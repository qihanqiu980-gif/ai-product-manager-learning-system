把 Prompt 放回产品系统：它是契约，不是万能补丁。

Prompt 的价值是把任务、输入、输出、语气、步骤和禁区说清楚。它能降低模型漂移，但不能凭空补齐缺失事实，也不能替代检索、工具执行、状态校验、质量评测和人工确认。

知道 Prompt 能约束什么，才不会把所有失败都归因于“提示词还不够好”。

再看失败

同样是回答不好，可能是指令不清、材料缺失、检索失败、规则缺失或需要人工确认。

Prompt 能做什么：把模型行为写成可执行任务契约

一个好的 Prompt 不是华丽话术，而是把任务目标、上下文、输出结构、判断步骤、禁止事项和失败处理说清楚。它让模型在已有信息内更稳定地完成任务。

任务目标

这次到底要完成什么

例如“根据候选人的项目回答，指出缺少的业务结果证据”。

不等于：笼统说“像资深面试官一样”

输入字段

模型可以使用哪些材料

例如 JD、简历段落、项目背景、用户回答和评分 Rubric。

不等于：让模型默认知道用户真实经历

输出结构

结果按什么格式交付

例如问题诊断、追问、改写建议、证据引用和下一步练习。

不等于：只要求“详细一点”
白话解释

Prompt 像给模型的任务单：写清它要读什么、怎么想、怎么输出、哪些话不能说。

它不等于什么

它不是资料库、不是后端接口、不是自动化工具，也不是正式评分系统。

错误写法你是最专业的 AI 面试官，请给我完美答案

没有输入字段、评分标准、输出格式和不能编造的边界，模型容易给出听起来合理但不可复核的建议。

产品化写法基于用户原回答和 Rubric，只指出证据缺口，并输出追问与改写建议

任务、材料、输出和禁止事项都清楚，才能成为可评测的产品能力。

完整示范：让 Agent 评价一个项目回答先写任务契约，再谈模型表现

场景：用户回答“我做了一个增长项目，效果很好”，但没有提供指标、角色和过程。

  1. 已知事实模型只有用户这句话，没有项目数据和结果证据。
  2. Prompt 可做要求模型指出缺少指标、角色、动作和结果，并生成追问。
  3. Prompt 不可做不能替用户编造增长率、团队规模或业务结果。
  4. 产品动作输出“信息不足 + 三个追问 + 可改写结构”，而不是直接给满分答案。

Prompt 不能补什么：先做失败归因，再决定是否改提示词

产品经理最容易犯的错，是把所有输出问题都归结为“Prompt 没写好”。W2D1 要练的是分类：哪些能靠 Prompt 改，哪些必须靠材料、检索、规则、工具或人工。

白话解释

Prompt 可以让模型更守规矩，但不能让模型知道未提供的信息，也不能保证事实、执行动作或承担正式责任。

它不等于什么

不是无限加指令，也不是把系统能力全写进一段提示词里。

错误归因模型漏引用证据，继续加一句“必须引用证据”

如果系统没有提供可引用材料或没有校验引用字段，Prompt 只能要求，不能保证。

正确归因先看材料、检索、格式校验和评测，再判断 Prompt 是否要改

同一个失败现象背后可能是不同系统原因，不能只修表层文字。

完整示范：Agent 评价偏泛泛时怎么办不要第一反应只改 Prompt
  1. 现象Agent 总说“建议补充量化结果”，但不能指出具体缺哪一段。
  2. 可能原因Rubric 不清、项目材料缺失、回答切片太粗、输出格式没有证据字段。
  3. Prompt 可修补充评分步骤、输出字段和禁止泛泛评价。
  4. Prompt 不可修如果没有项目材料或引用机制，需要补资料结构或 RAG，而不是继续堆指令。

材料与上下文边界：没有输入，就不要要求模型给确定结论

AI 面试与项目答辩教练 Agent 的核心材料包括 JD、简历、项目经历、用户回答、Rubric 和历史反馈。Prompt 必须声明材料边界，并在材料不足时触发追问或不确定标注。

白话解释

材料边界就是告诉模型“你只能根据这些内容判断；缺的要问，不准编”。

它不等于什么

不是把用户没给的信息包装成“合理推测”，也不是让模型代替候选人虚构经历。

可用材料

可以引用

用户上传或输入的 JD、简历、项目原文、回答记录和评分标准。

缺失材料

必须追问

项目结果、个人贡献、业务背景、指标来源和约束条件。

不确定信息

必须标注

无法从材料证明的事实只能标记“不足”，不能写成确定结论。

完整示范：用户只给了岗位 JD，没有简历Prompt 应触发追问，不是直接打分
  1. 已有材料JD 能说明岗位能力要求。
  2. 缺失材料没有候选人经历、项目证据和回答原文。
  3. 允许输出可以输出“可能考察点”和“需要补充的材料清单”。
  4. 禁止输出不能输出候选人的项目评分或是否匹配岗位的确定结论。

模型 / 规则 / 人工分界：Prompt 只负责表达和推理引导的一部分

W2 的技术选型从这里开始：不是所有问题都上 RAG，也不是所有问题都靠 Prompt。你需要把表达引导、事实引用、状态动作、质量门槛和高风险结论分配给不同机制。

白话解释

把 Agent 想成一个小系统：Prompt 负责让模型按任务说话；规则负责硬约束；RAG 负责找资料；工具负责执行动作；人工负责高风险确认。

每层职责清晰，后续可以做评测、日志和发布门槛。

完整示范：答辩评分应如何拆层评分建议不等于正式通过
  1. Prompt根据 Rubric 输出初步诊断、追问和改写建议。
  2. 规则检查是否覆盖背景、行动、结果、反思和证据引用。
  3. 资料/RAG从项目材料中找可引用的事实和历史反馈。
  4. 人工确认是否作为正式答辩材料或简历表达。
