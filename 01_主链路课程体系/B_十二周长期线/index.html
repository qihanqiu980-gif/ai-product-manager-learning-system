当前主线

原十二周长期线压缩为 W1-W5。W6-W12 不作为当前主线展示，后续如需要再单独设计为扩展模块。

与已有课程的关系

1-19 课和两周课程只作为素材库。本线不重复照搬，而是把知识转化为一个可演示、可解释、可迭代的 Web Agent 产品。

每日课程拆解

每周 5 天，每天都有明确学习点、项目任务和可交付物。

W1

项目定义与边界

先把“为什么做、给谁用、解决什么问题、哪些不做”讲清楚，再进入方案与工程。

产出：MVP 定义文档
W1D1

项目问题定义

明确 AI 面试与项目答辩教练 Agent 要解决的核心痛点。

  • 学习 AI Agent、AI 产品、面试教练的基础定义。
  • 拆解目标用户在面试准备中的真实任务。
  • 写出问题陈述和成功标准。
W1D2

用户与场景边界

从泛面试训练收敛到具体使用场景。

  • 定义候选人、岗位、项目材料、答辩场景。
  • 区分高频、低频和暂不支持场景。
  • 沉淀用户画像与任务清单。
W1D3

Agent 基础模型

理解项目里的 Agent 是输入、推理、追问、反馈的任务系统。

  • 学习模型、Prompt、上下文、工具调用的关系。
  • 画出教练 Agent 的最小工作链路。
  • 判断哪些能力需要 LLM，哪些只需规则或页面逻辑。
W1D4

能力边界与风险

明确产品不能承诺什么，以及错误输出如何被识别和控制。

  • 学习幻觉、过度建议、隐私、错误评分等风险。
  • 定义产品边界、免责声明和人工复核点。
  • 形成风险清单与限制策略。
W1D5

MVP 范围确认

把第一周内容收束成一个可以继续做下去的 MVP。

  • 确定首版核心能力。
  • 写出功能清单、非功能清单和验收口径。
  • 产出项目定义文档 v1。
W2

产品方案拆解

把抽象 Agent 变成可描述、可实现、可评审的产品方案。

产出：产品方案 v1
W2D1

核心用例拆解

把面试教练拆成输入材料、生成问题、模拟追问、反馈改写等核心用例。

  • 学习 Use Case、用户故事和验收条件。
  • 为每个用例写清输入、动作、输出。
  • 标记首版必须做和暂不做的范围。
W2D2

Prompt 任务设计

将“教练感”拆成系统角色、任务指令、约束和输出格式。

  • 学习 Prompt 的角色、目标、上下文和格式约束。
  • 设计模拟面试、追问、评分、建议四类 Prompt。
  • 形成 Prompt 模板 v1。
W2D3

知识输入结构

确定用户材料如何进入系统，避免把 RAG 当成空泛概念。

  • 学习知识库、检索、上下文注入的基本概念。
  • 设计简历、项目说明、岗位 JD 的字段结构。
  • 判断首版是否需要 RAG，或用结构化输入替代。
W2D4

反馈策略设计

定义 Agent 如何指出问题，而不是只给泛泛建议。

  • 学习诊断式反馈、示例反馈、改写反馈的差异。
  • 设计评分维度、证据引用和改进建议。
  • 形成反馈结构样例。
W2D5

方案规格沉淀

把第二周内容收束成一份能直接交给设计、工程和后续评审使用的产品规格。

  • 回看 W2D1-W2D4 的用例、Prompt、输入结构和反馈策略。
  • 统一术语：角色、输入、输出、约束、边界、异常场景。
  • 整理成一页式产品规格，写清首版做什么、不做什么。
  • 补齐验收口径：什么样的输出算可用，什么情况需要重写或人工处理。

今日节奏： 上午整理前四天内容，下午补齐规格和边界，收尾完成自检和版本命名。

当日交付： 1 页产品规格草案 + 1 份验收口径清单 + 1 版可继续推进的方案 v1。

完成标准： 能明确讲清这个 AI 面试与项目答辩教练 Agent 的核心流程、字段、输出样式、风险边界，以及产品方案 v1 的下一步要怎么进入流程与评测。

W3

流程与评测体系

补齐交互、状态、质量标准和测试样本，避免只做一个聊天壳。

产出：流程与评测包
W3D1

用户流程设计

设计从上传材料到完成一次模拟答辩的完整路径。

  • 学习用户流程、任务路径和关键节点。
  • 画出首版用户流程图。
  • 明确每一步页面需要承载的信息。
W3D2

状态机与异常

定义加载、生成、失败、重试、追问、完成等状态。

  • 学习状态机、异常流和兜底文案。
  • 列出关键状态与转移条件。
  • 补齐错误提示和重试策略。
W3D3

Rubric 评分

建立 Agent 反馈的评分标准，减少主观和空泛。

  • 学习 Rubric、评分维度和等级描述。
  • 设计项目答辩回答的评分表。
  • 写出优秀、一般、风险回答样例。
W3D4

Eval Set 构建

准备一组能反复验证 Agent 质量的测试样本。

  • 学习 Eval Set、测试样本和预期输出。
  • 构造不同岗位、项目、回答质量的样本。
  • 定义通过、警告、不通过标准。
W3D5

产品评测闭环

形成从样本到评分到修正 Prompt 的闭环。

  • 跑一轮手工评测。
  • 记录 Badcase、原因和修正方案。
  • 产出流程与评测包 v1。
W4

Web 原型与工程落地

把方案变成用户能打开、能输入、能得到反馈的 Web 产品原型。

产出：可演示 Web MVP
W4D1

Web 信息架构

定义页面、模块、输入区、对话区、反馈区和记录区。

  • 学习 Web 产品的信息架构和页面层级。
  • 画出首版页面结构。
  • 确认用户从进入到完成训练的路径。
W4D2

核心页面原型

完成材料输入、模拟问答、评分反馈三个核心页面或区域。

  • 学习表单、对话、反馈面板的基本交互。
  • 搭出低保真或静态 HTML 原型。
  • 检查信息是否完整、清晰、可操作。
W4D3

API 与数据流

理解页面、后端接口、模型调用和返回结果之间如何连接。

  • 学习 API、请求体、响应体、错误码基础。
  • 设计 Agent 调用的数据流。
  • 明确哪些字段必须被记录和展示。
W4D4

日志与记录

让每一次训练结果可追踪，方便后续优化。

  • 学习日志、事件、会话记录的基本概念。
  • 设计训练记录、评分记录、Badcase 记录。
  • 形成最小数据记录方案。
W4D5

可演示版本

把本周内容串成一次完整演示。

  • 跑通一次从输入到反馈的主流程。
  • 记录演示脚本和已知问题。
  • 产出可演示 Web MVP v1。
W5

打磨与稳定

围绕真实使用质量做修正，不转向泛商业化或求职包装。

产出：最终项目包
W5D1

Badcase 分析

集中审查 Agent 输出错误、空泛、跑偏和不可用的情况。

  • 收集至少一组典型 Badcase。
  • 区分 Prompt、输入、流程和评测问题。
  • 形成修正优先级。
W5D2

质量与护栏

补齐产品必须具备的质量底线。

  • 学习安全边界、拒答、降级和人工提示。
  • 为隐私、误导建议、过度承诺建立护栏。
  • 更新 Prompt、页面提示和评测规则。
W5D3

成本与体验优化

让产品更像可长期使用的工具，而不是一次性 Demo。

  • 学习 token 成本、响应时长和缓存的基本判断。
  • 优化输入长度、输出结构和等待体验。
  • 形成成本与体验优化清单。
W5D4

项目说明材料

写清这个 Agent 是怎么被定义、设计、实现和评测的。

  • 整理项目背景、功能范围、技术链路和质量方案。
  • 补充关键截图、流程图和评测结果。
  • 形成项目说明文档。
W5D5

最终演示复盘

完成最终演示，并明确后续迭代方向。

  • 按真实用户路径演示完整流程。
  • 复盘产品价值、Agent 能力和工程限制。
  • 产出最终项目包和下一版迭代清单。
