旧知识盘点到底盘什么？

不是把第 1-19 课重新看一遍，而是把“能解释、能应用、有证据”和“只是熟悉名词”分开。

0 / 2 步

课程记录

已经留下的学习事实

它说明曾经学过什么、提交过什么、哪里通过或未通过。

能看见：历史题目、学习提交、页面记录不能决定：未来是否自动掌握

能力证据

能支撑判断的原始材料

它可以是回答、Demo、PRD、架构说明或实验记录。

能证明：某个判断如何得出不能替代：新场景迁移验证

缺口清单

本周必须补的少数问题

它只收真正影响后续课程的缺口，不把所有不熟悉名词都塞进 W1。

能决定：本周练习优先级不能变成：无限复习列表
白话解释

盘点就是把学习历史变成一张库存表：哪些货架上有可用证据，哪些位置只有标签没有内容。

它不等于什么

它不是补看全部旧课，也不是凭感觉打勾。没有证据的熟悉感，只能记为待验证。

看起来认真，但错误第 1-19 课全部重刷

时间被熟悉内容吃掉，真正卡住后续课程的缺口仍没有被定位。

正确的产品链路证据 → 能力判断 → 缺口优先级 → 本周动作

先看已有记录，再决定哪些能力需要解释、应用或迁移验证。

完整示范：Prompt 知识看起来熟先找证据

现象：学习者说自己懂 Prompt，但找不到能说明失败恢复和输出约束的记录。

  1. 已知事实有概念印象，但缺少可复核输出。
  2. 第一个错误节点把熟悉感当作通过证据。
  3. 正确动作把它列为“待迁移验证”，安排一个小场景重答。
  4. 保持不变任何旧知识都先看证据权限，再决定是否进入 W1。

需要提示时展开

第 20 课的“结束规则”为什么必须先补？

长期线会有更多实验和评测，如果不知道什么叫正常完成、提前结束和最低证据，后续每周都会变成拖延或假完成。

0 / 2 步
白话解释

结束规则就是课程的刹车和验收口：什么时候继续，什么时候停止，停止时至少留下什么证据。

它不等于什么

它不是“学到满意为止”，也不是“时间到了就算结束”。没有最低证据，提前结束只是中断。

看起来灵活，但错误状态不好就提前结束

没有写清结束条件和证据，下一次无法恢复，也不知道缺口在哪里。

正确的产品链路触发条件 → 最低证据 → 恢复入口 → 后续依赖

结束不是消失，而是让当前学习状态可解释、可恢复、可承接。

完整示范：今天只能学 40 分钟先保留最低证据

现象：学习者无法完成全部 W1 模块，但已经完成旧知识盘点。

  1. 已知事实时间不足，但已有一个可复核盘点产物。
  2. 第一个错误节点直接关闭页面，下一次不知道从哪里接。
  3. 正确动作保存盘点、标记未完成模块、写下一步恢复入口。
  4. 保持不变任何提前结束都要留下当前事实、缺口和恢复动作。
理解检查：提前结束前先做什么

你已经完成一半 W1，但不能继续。第一步应该是什么？

带着资料做一次：写一个 W1 提前结束规则

为 W1 写出正常完成、提前结束、最低证据和恢复入口。

需要提示时展开

分别写四句：完成标准是什么，何时允许停止，至少保存什么，下次从哪里恢复。

方案已记录。

正常完成：五个模块与综合制定稿完成；提前结束：至少保存一个模块的归类或规则；最低证据：当前事实、未完成缺口、下一步恢复入口；恢复入口：回到最后未完成模块并读取理解地图。

平台 Agent 跑通为什么不是“点一下看看”？

跑通的意思是把输入、工具动作、输出、失败提示和可复现记录连起来。只看到一次成功截图，不足以支撑长期线项目。

0 / 2 步
白话解释

平台 Agent 是本周的最小工作流样机。它要证明你能让工具按业务任务走一遍，而不是只会打开产品界面。

它不等于什么

它不等于完整自动化，也不等于炫技 Demo。W1 只要求能复现、能说明边界、失败后知道怎么处理。

看起来跑通，但错误成功一次 → 截图 → 结束

没有输入样本、工具步骤和失败处理，下一周无法基于它迭代。

正确的产品链路任务边界 → 输入样本 → Agent 动作 → 输出检查 → 失败记录

把一次运行变成后续课程可以复用的项目证据。

完整示范：让 Agent 生成课程摘要先限制任务

现象：Agent 可以生成摘要，但会把没有证据的掌握状态也写进去。

  1. 已知事实输入是课程页面和学习记录，正式掌握只能来自状态源。
  2. 第一个错误节点让 Agent 自行判断掌握状态。
  3. 正确动作限制输出为摘要草稿和待核对项，掌握状态只引用正式 JSON。
  4. 保持不变任何 Agent 工作流都要区分生成草稿和正式事实。

示例任务：读取两周突击线页面标题和学习状态快照，生成“已有证据 / 待补缺口 / 不处理项”草稿表；输出不得写正式掌握，只列来源、判断理由和待人工确认项；失败时保留输入列表和错误提示。

为什么 W1 要做证据看板，而不是只写学习计划？

长期线会持续产生笔记、实验、Demo 和评测记录。没有证据看板，后面十二周会失去“哪些能力已经有材料支撑”的判断依据。

0 / 2 步
白话解释

证据看板就是学习项目的物流单：每个能力点对应哪些材料，材料现在能证明什么，还缺哪种验证。

它不等于什么

它不是漂亮进度条，也不是把所有文件堆在一起。看板必须能帮助你做下一步课程决策。

看起来清楚，但错误用百分比表示掌握度

百分比无法说明证据来源、权限和缺口，容易制造完成感。

正确的产品链路能力点 → 证据来源 → 能证明什么 → 还缺什么 → 下一动作

让每个进度都能回到具体材料和后续动作。

完整示范：Web Demo 已经存在不要直接写完成

现象：项目里有 Web 页面，但还没有移动端、失败恢复和成本记录。

  1. 已知事实Demo 可运行，覆盖部分功能证据。
  2. 第一个错误节点把“页面存在”写成“工程化能力完成”。
  3. 正确动作看板标为“已有运行证据，缺恢复、移动和成本”。
  4. 保持不变证据看板记录的是证据范围，不是情绪化进度。
