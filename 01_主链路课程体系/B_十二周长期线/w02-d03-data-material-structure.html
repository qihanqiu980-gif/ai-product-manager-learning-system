材料清单怎么列：先把来源和范围说清楚

材料清单决定后续能不能检索和引用。没有清单，材料就只是散落的文件。

0 / 2 步

来源

有哪些文档

JD、简历、项目经历、Rubric、答辩记录、作品集。

权限

谁能看

哪些材料允许检索、展示和引用。

版本

哪一版有效

更新时间、版本号和来源标识。

白话解释

材料清单像仓库总表：先知道仓里有什么、谁能拿、哪一版是新的，再去设计后面的检索和评分。

它不等于什么

它不是把所有文件丢给模型，也不是只写一个模糊的“数据集”。

错误写法把所有资料统一放进去，后面再说

没有来源、权限和版本，就不知道什么能引用、什么已经过期。

产品化写法先列来源清单、权限和版本，再决定检索与引用

材料清楚，后续才知道怎样切片、怎样查找、怎样更新。

完整示范：面试教练的来源清单先列材料，再谈结构
  1. 已知来源用户上传了 JD、简历、一个项目复盘和一份答辩记录。
  2. 材料边界这几个来源允许当前用户检索，但版本需要标清。
  3. 后续用途RAG、评分和追问都要能回到这些来源。
  4. 产品动作先做材料清单，再决定字段和切片规则。

材料结构不能补什么：先辨认是结构问题还是提示词问题

材料结构不是万能修补器。缺字段、缺版本、缺权限、缺来源，和 Prompt 本身写得不好是不同问题。

0 / 2 步
白话解释

结构问题是“输入长什么样”，提示词问题是“模型该怎么说”；两者不能混为一谈。

它不等于什么

它不是把所有失败都推给数据工程，也不是把所有问题都推给 Prompt。

错误归因答案不好，就继续改提示词

如果问题是字段缺失或版本错误，Prompt 再长也救不了。

正确归因先看材料结构，再判断要不要改 Prompt

先分清是结构、字段、版本、权限还是表达问题，再决定下一步。

完整示范：为什么模型找不到项目结果先判断结构，再判断提示词
  1. 现象Agent 总说“缺少项目结果”，但没法定位到底缺哪一项。
  2. 结构问题项目材料没有拆出“指标、角色、时间、版本”等字段。
  3. 提示词问题如果字段已经有了，才考虑补充提示词里的引用规则。
  4. 产品动作先补材料结构，再决定是否改 Prompt。

切片与字段边界：字段负责结构，切片负责检索

字段和切片不是一回事。字段决定能不能稳定引用，切片决定能不能准确检索。

0 / 2 步

字段

保留什么信息

版本、来源、项目、指标、角色、时间和权限。

切片

怎么拆更好查

按项目、按答案段落、按评分维度或按版本拆开。

引用键

怎么回到原文

每个结论都能定位到原始材料与对应版本。

白话解释

字段像表头，切片像把长文拆成可查的小块；两者一起决定后续 RAG 能不能稳定工作。

它不等于什么

它不是把整份文件直接塞给模型，也不是只切得越碎越好。

危险写法整个项目文档直接丢给检索，反正模型会自己找

没有字段和引用键，后续根本不知道结果从哪里来。

更稳的写法字段先定义，切片再按项目和评分维度拆开

后续 RAG、评分和追问都能回到原始版本和来源。

完整示范：项目答辩材料怎么切字段和切片分开做
  1. 字段版本号、项目名、结果指标、角色和时间。
  2. 切片按“背景 / 动作 / 结果 / 反思”拆成片段。
  3. 引用键每个片段都能回到原始答辩记录。
  4. 产品动作字段和切片一起设计，后续 RAG 才能引用。

数据 / Prompt / RAG / 人工分界：把职责拆开，Agent 才好治理

W2 的结构化数据不负责表达，也不负责最终结论。它负责让来源、版本、字段和状态可被后续机制使用。

0 / 2 步
白话解释

数据结构负责把材料变成表头、字段和版本；Prompt 负责怎么说；RAG 负责引用；人工负责确认。

它不等于什么

它不是把所有职责都塞进一个表单，也不是让模型自己猜字段。

危险分工材料结构、检索逻辑和正式结论都混在一起

这样一旦失败，后面不知道该改哪一层。

可治理分工数据先搭好，再让 Prompt 和 RAG 用它

职责清楚后，后面才能做评测、日志和改版。

完整示范：材料清单怎么接到后续系统先建数据，再接后续
  1. 数据材料来源、版本和权限先记录好。
  2. Prompt表达任务和追问时引用结构化字段。
  3. RAG检索对应原文和片段。
  4. 人工确认是否写入正式答辩材料或作品集。
