模型更懂回答，为什么不能让它直接决定下一步？

模型擅长理解语义和生成候选；程序掌握真实状态、上限、权限和失败恢复。两者不是谁更聪明的问题，而是谁拥有哪类事实和责任。

0 / 2 步
白话解释

机场停飞可能因为机械故障、旅客取消、航程正常结束或时间耗尽。它们都是“停”，但原因、动作和后续完全不同，不能一律盖章“已完成”。

它不等于什么

degraded → exit_confirmation_pending → completed 不是固定顺序。没有退出请求就不进入等待确认；校验未通过也不能因业务题目做完而进入完成。

1 · 最高优先degraded

自动结果不可信：止损、留证、人工或受控恢复。

2exit_confirmation_pending

用户主动请求退出：保存进度，等待明确确认。

3completed

题数、覆盖、保存和校验全部通过，才冻结交付。

4limited_report

必须结束但覆盖不完整：只报告已有有效证据和限制。

5continue

仍可继续且存在必要缺口：生成合法下一题。

错误判断questions_done = true → completed

忽略保存失败、输出校验、覆盖缺口、退出请求和更高优先级异常。

先收集同一时刻事实，再按优先级选一个分支并执行对应动作。

进入 degraded 之后，为什么“查日志、改提示词”还不够？

安全降级不是一个错误标签，而是一套先止损、再保留失败现场、最后受控恢复的可执行动作。没有交付阻断和完整现场，团队可能继续扩散错误，也无法复现问题。

0 / 2 步
白话解释

它像发现食品批次可能污染：第一步是立刻封存并停止出货；第二步保留批次、检测、设备和操作记录；第三步才是人工检查、隔离复测和重新放行。

它不等于什么

“系统报错了”“稍后重试”“优化 Prompt”都不是完整降级方案。修复动作也不能覆盖旧失败现场，更不能未经同一交付校验直接变成 completed。

Layer 1立即止损

停止自动重试，阻止未校验输出进入报告或下游，触发告警。

Layer 2保留失败现场

冻结原始输入、模型输出、校验错误、重试次数、版本与日志。

Layer 3受控恢复

人工复核或隔离重试；新尝试关联旧记录，重新通过同一校验后才放行。

危险处理validation failed → retry forever → overwrite old output

故障持续消耗资源，旧现场丢失，未校验结果可能继续流向下游。

安全处理block → freeze evidence → alert → controlled recovery → revalidate
