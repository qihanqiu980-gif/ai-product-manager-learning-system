先在脑中搭起一条链：一个分数怎样才有资格进入报告。

把评分想成一次“有证据的裁决”。原始回答是现场记录，逐字引用是证物，有限结论说明证物能证明什么，评分规则规定如何映射到等级，引用编号让审核者能回到当时的版本。任何一步断开，分数就应该停下或变成不可评分状态。

先看证据，再看分数

先问原话在哪里、直接支持什么，再讨论匹配哪个等级。

用错误方案建立边界

重点识别“引用是真的但结论说多了”“200 字回答看起来像高分”等诱人捷径。

带着资料做新场景

练习允许看提示和示例，目标是写出可复核记录，不是背定义。

保留 question_id、answer_id 和逐字内容。

→

看似高效，但不可发布answer → model score → report

可复核的产品链answer → quote → limited claim → published rubric → score/status → reference

每一步都有输入、责任人、失败状态和回放依据。

模型已经给了 3 分，为什么还要先发布评分规则？

评分量表（Scoring Rubric）不是分数展示组件，而是一份评分发生前就要确定的评价协议：评价什么、各等级能观察到什么、需要哪些证据、什么情况不能评分。

0 / 2 步
白话解释

它像跳水比赛的评分规则：选手上场前，动作难度、扣分条件和通过线就已经写好，不能看完表现后再临时发明一套标准。

它不等于什么

它不是模型“根据感觉生成一个分数”，也不是把 0–3 画成漂亮进度条。没有预先定义的维度、锚点、证据和不可评分条件，就没有稳定尺度。

Dimension只评价一个维度

例如“上线验证能力”，不混入表达流利度。

Anchor每一级可观察行为

写出 1、2、3 分之间真正多了什么。

Evidence Rule必要证据

哪些原话和事实才能支撑该等级。

Boundary通过与不可评分

通过线、未覆盖、证据不足和版本要求。

诱人捷径长回答 + 专业词多 = 3 分

评价被文风和长度污染，真正的决策行为反而不可见。

正确判断observable evidence → published anchor

只检查已发布锚点要求的可观察行为，不给无关信息加分。

完整示范：模型建议 3 分先核对评分协议

原话：“上线前会测准确率和响应时间。”规则中 2 分要求两个指标；3 分还要求停止阈值、审核记录和恢复条件。

  1. 已知事实原话直接给出两个指标，没有停止、记录或恢复。
  2. 第一个错误节点模型建议 3 分，但证据只满足 2 分锚点。
  3. 正确动作程序拒绝 3 分，按已发布 v1 规则得到 2 分并保留引用。
  4. 保持不变无论面试、客服还是质检，分数都必须服从评分前发布的证据锚点。
理解检查：专业术语多能不能自动加分

候选人用了很多 AI 术语，却没有说明选择、风险或重评条件。Rubric 的 2 分锚点要求“基于约束做出选择并给出验证指标”。第一步怎么处理？

带着资料做一次：客服质检的合规 Rubric

为“遇到政策不确定时是否安全处理”写一个 0–3 分规则，并明确通过线与不可评分条件。

需要提示时展开
  • 0 分要有足够的负向证据，不能等于“没看到”。
  • 2 分和 3 分之间要有一个可观察增量。
  • 写出未覆盖与证据不足时为什么不能给数字。

规则已记录。检查相邻等级是否真的存在可观察差异。

0 分：已观察到在政策不确定时仍承诺退款；1 分：只泛称必要时转人工；2 分：识别不确定、停止自动承诺并转人工；3 分：在 2 分基础上记录触发规则、审核记录和恢复条件。通过线至少 2 分；未提问为 not_observed，提到政策但细节不足为 insufficient_evidence。

留下一个理解或疑问

记录“评分规则”和“模型分数”之间你刚刚分清的一层关系。

同一段回答，为什么不能只凭“整体感觉”选 1、2、3 分？

锚点把等级差异写成可以观察和复核的行为；模型、程序与人工共同参与，但没有任何一方可以独自包办规则、证据和发布。

0 / 2 步

Model / 模型

提出候选证据与分数

可以摘取 quote、生成有限 claim、建议 criterion 和 score。

不能：定义临时规则或最终发布

Program / 程序

按已发布规则做确定性检查

核对原文、版本、锚点、状态和聚合规则。

负责：阻止越界分数进入报告

Human / 人工

承担规则与高风险责任

定义或批准 Rubric，处理语义争议、冲突证据和版本变更。

不能：无证据凭印象补分
白话解释

锚点像楼梯上的清晰台阶：2 分不是“还不错”，而是能指出哪些具体行为已经出现；3 分必须再多出哪些行为。

它不等于什么

模型置信度、回答长度和审核者直觉都不是锚点。人工复核也不能绕过证据，只能解决已发布规则无法自动裁决的争议。

错误分工Model extracts → Model scores → Model publishes

同一方同时创造证据解释和最终结论，无法阻止自洽但错误的高分。

正确分工Model proposes → Program validates → Human owns rule / dispute

概率性候选、确定性校验和责任性裁决保持分离。

完整示范：3 分缺少最后一层证据逐项排除而不是凭感觉

规则：2 分要求“发现风险并停止自动处理”；3 分还要求“记录触发器、审核记录、恢复条件”。原话只覆盖前两项。

  1. 已知事实停止动作可观察；记录和恢复没有出现。
  2. 第一个错误节点若因回答听起来成熟就给 3 分，会跳过必要证据。
  3. 正确动作模型建议 2 分；程序核对字段与锚点；若原话歧义再交人工复核。
  4. 保持不变相邻等级必须由可观察增量区分，不能由“总体印象”区分。
理解检查：模型建议 3 分但只满足 2 分锚点

销售陪练 Rubric 的 3 分要求“识别异议、给出证据、约定下一步”，原话只有前两项。谁来做什么？

带着资料做一次：销售陪练的相邻等级

为“处理价格异议”写出 1、2、3 分之间的可观察增量，并注明模型、程序、人工各自的发布职责。

需要提示时展开

先列出 2 分比 1 分多什么，再列出 3 分比 2 分多什么；最后说明哪个检查可以由程序确定完成。

锚点已记录。检查每一级是否能由观察到的原话或动作区分。

1 分只重复价格信息；2 分能复述异议并用一条与需求相关的价值证据回应；3 分在 2 分基础上确认异议是否解除并约定下一步。模型提候选证据与分数；程序核对 quote、criterion、版本和必要字段；人工批准 Rubric 并处理语义争议。

留下一个理解或疑问

记录一条相邻等级必须怎样区分，或三方职责中仍拿不准的地方。

引用是真话，为什么结论仍可能越界？

事实锚定（Grounding）不只检查“有没有引用”，还检查这句逐字证据是否真的能推出当前结论。真实 quote 也可能被配上一个说多了的 claim。

0 / 2 步
白话解释

原话是地基，结论是盖在上面的房子。地基是真的，不代表可以在上面随意多盖三层；结论范围必须小于等于证据直接支持的范围。

它不等于什么

关键词重合不等于蕴含；语义听起来合理也不等于被原话证明。模型自信度不能替代逐字来源和范围检查。

Quote逐字来自当前 answer_version

先验证来源、位置和文本完全匹配。

Limited Claim只说原话直接支持的事

删除动机、频率、结果等未出现的信息。

Criterion Fit结论与评价条件同维度

真实引用不能支撑无关能力。

真实引用＋越界结论“会测准确率” → “已建立完整质量体系”

引用存在，但“完整体系”包含未观察到的流程、频率和责任。

证据允许的有限结论“会测准确率” → “提出准确率作为上线前指标”

结论停在原话实际提供的信息范围内。

完整示范：一句话被扩大成完整体系先圈出新增事实

原话：“上线前会测准确性和响应速度。”候选 claim：“已建立持续监控、回归测试与故障处置体系。”

  1. 已知事实只观察到两个上线前指标。
  2. 第一个错误节点claim 新增了持续监控、回归频率和故障处置。
  3. 正确动作拒绝越界 claim，缩小为“提出两个上线前指标”；相应分数只按该有限结论判断。
  4. 保持不变任何报告结论都不能超过逐字证据可直接支持的范围。
理解检查：引用真实能否保住扩大后的结论

政策助手引用“特殊情况转人工”，却总结成“团队已建立完整升级和审计机制”。第一步怎么做？

带着资料做一次：政策问答助手的有限结论

原文写“申请人可以在 30 日内补交材料”，模型回答却增加了“逾期一定自动拒绝”。请拆出可发布 claim、越界部分和处理动作。

需要提示时展开

先逐字写出原文支持的范围，再单独列出模型新增的因果或规则；无法核实的部分应删除或标注 limitation。

有限结论已记录。检查 claim 是否严格小于等于 quote 支持范围。

可发布 claim 只能是“允许在 30 日内补交材料”；“逾期一定自动拒绝”没有来源支持，应删除或明确标记当前证据未说明逾期结果，不得用模型推断补齐规则。

留下一个理解或疑问

记录“有引用”和“被引用支持”为什么不是一回事。

报告里有原话，为什么修改答案后还要让旧引用失效？

可追溯性（Traceability）让审核者从结论返回原题、原答、字符位置、评分规则和当时版本。只保存一段文本，没有版本和身份，仍无法证明它属于哪次评分。

0 / 2 步
白话解释

它像快递单号加时间戳：不仅知道包裹里写了什么，还知道来自哪一单、哪个版本、由哪套规则处理，之后是否被修改。

它不等于什么

复制一段原话到报告不等于可追溯；只有 answer_id 没有 answer_version 也不够。源内容变化后，旧位置和旧分数不能静默继续有效。

Source Identityquestion_id + answer_id

确认引用属于哪道题和哪次回答。

Versionanswer_version + checksum

确认评分看到的是哪一版文本。

Locationquote_span

从报告定位回原文字符范围。

Rule Identitycriterion_id + rubric_version

确认当时按哪套规则评分。

Auditaudit_id + reviewed_at

记录谁在何时验证或复核。

脆弱引用{ quote: "……", answer_id: "a17" }

回答更新后，系统不知道引用来自旧版还是新版，也不知道旧分数是否应重算。

可回放引用a17:v2#28-43 · rubric-v3 · audit-09

身份、版本、位置、规则和审计记录共同构成引用。

完整示范：answer v2 已经改写旧引用不能静默存活

现象：报告引用 ans-17:v1#28-43；用户修订回答后系统生成 v2，原字符位置内容不同。

  1. 已知事实报告绑定 v1；当前回答是 v2。
  2. 第一个错误节点若仍把旧分数显示为当前有效，会隐藏证据版本变化。
  3. 正确动作旧引用标记 stale，保留历史；按 v2 重新提取、校验和评分后发布新版本。
  4. 保持不变任何可编辑来源都要让引用绑定版本，并在来源变化后失效或重算。
理解检查：原回答改版后旧分数怎么办

采购评审记录绑定 proposal v1，供应商已经提交 v2。页面应该怎样处理旧评分？

追溯记录已保存。检查审核者能否从结论无歧义返回当时来源。

记录为什么“引用文本”还必须绑定来源版本。

没有证据，为什么不能直接写成“能力较低”？

“没问到”“提到了但不够判断”“证据足够且表现较低”是三种不同事实。报告必须先确定状态，再决定能否发布数字分数和怎样描述限制。

0 / 2 步
not_observed没有被观察

题目或流程没有覆盖这个维度，不能推断能力高低。

insufficient_evidence相关但证据不足

触及了维度，却不足以稳定匹配任何锚点。

low_score已有充分负向证据

被观察且证据足够，只是表现确实位于低等级。

白话解释

没拍到并不等于没发生；拍到模糊影像也不等于已经看清；只有看清了具体行为，才能说它落在哪个等级。

它不等于什么

score=0 不能同时表示未提问、回答太少和明确错误。把它们压成一个数字，会让用户、运营和后续流程采取错误动作。

错误报告未收集证据 → 能力不足 → 0 分

把产品没有覆盖到的责任转嫁给被评价者。

诚实报告coverage + evidence → status → allowed wording

先判定覆盖和证据，再选择分数、不可评分状态与 limitation。

完整示范：题目没有问协作能力不把缺数据写成缺能力

现象：整个面试没有出现跨团队协作题，报告模板却要求协作分数。

  1. 已知事实该维度未覆盖，没有相关回答。
  2. 第一个错误节点若填 0 分，会把产品采样缺口伪装成负向能力证据。
  3. 正确动作发布 not_observed、score=null，说明未覆盖并给出后续补充动作。
  4. 保持不变没有观察到永远不能单独证明能力低。
理解检查：相关回答太短时是哪种状态

培训助手问了“如何验证上线效果”，用户只答“会测试”，没有指标、样本或条件。应该怎样发布？

带着资料做一次：入职培训能力报告

为“未提问、提问后只答一句、给出明确错误步骤”分别写 status、score、报告句式和下一步动作。

需要提示时展开
